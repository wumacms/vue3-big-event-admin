## Mock 层重构：axios adapter → MSW 3.x

- 动机：原自定义 axios adapter（466 行）需手写 AxiosResponse、parseBody、method 字符串分发，且请求不经过网络层，DevTools Network 面板看不到
- 方案：MSW 3.0.3（Service Worker）。`src/mock/handlers.ts` 用 `http.get/post/put/delete` 声明式定义接口，`browser.ts` 启动 worker，`db.ts` 保留数据与 localStorage 持久化
- 切换真实后端：`.env` 的 `VITE_USE_MOCK=false`，业务代码零改动；实测关闭后 MSW 的 401KB chunk 被 tree-shake，不进产物
- 单测复用同一套 handlers：`src/test/setup.ts` 用 `setupServer(...handlers)`，vitest setupFiles 挂载
- 坑：
  - MSW 3.x 把 `onUnhandledRequest` 改名为 `onUnhandledFrame`
  - Service Worker 只能拦截同源且在自身 scope 内的请求：mock 模式 baseURL 必须是 `BASE_URL` 去尾斜杠，handler 路径用 `api('/xxx')` helper 拼前缀，否则 GitHub Pages 子路径部署拦截不到（已用 preview 实测 scope=/vue3-big-event-admin/ 通过）
  - `msw init public/ --save` 生成 mockServiceWorker.js 并在 package.json 写入 msw.workerDirectory
  - 安装需 `corepack pnpm@12.16.1`（本机 pnpm 10 store 不兼容）
- 顺带修复：request.ts 的 HTTP 错误分支原先 reject 原始 axios error（调用方拿到 "Request failed with status code 401"），改为 reject 带业务文案的 Error
- 验证：type-check / lint / test(16) / build 全绿；Playwright 实测 dev 与子路径 preview 下 Network 均可见 /api 请求且 `from service worker`，完整业务流程冒烟通过
